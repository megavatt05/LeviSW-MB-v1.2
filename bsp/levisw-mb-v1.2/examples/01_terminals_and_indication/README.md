# Пример 01: Входные/выходные клеммы и локальная индикация (LeviSW-MB v1.2)

Данный проект демонстрирует программное управление и мониторинг аппаратного **Узла 01** («Входные/выходные клеммы и локальная индикация», Лист 2 принципиальной схемы `Switcher.SchDoc` платы **LeviSW-MB v1.2**).

Поддерживаемая среда: **ESP-IDF >= 5.2** (целевой микроконтроллер: `ESP32-PICO-V3`).

---

## Архитектура и схемотехника Узла 01

### 1. Входной клеммник магистрали XP1 (INTERCOM, 9-pin)
Подключает материнскую плату к внешнему подъездному домофону и источникам питания:

| Клемма XP1 | Сигнал схемы | Контрольные точки | Назначение в системе |
|---|---|---|---|
| `XP1:1` | `+VIN` | `TP1`, `TP4` | Вход внешнего нестабилизированного питания (12–24 В) |
| `XP1:2` | `-VIN` | `TP2`, `TP5` | Общий провод питания (GND платы) |
| `XP1:3` | `A` (RS-485-A) | `TP3`, `TP48` | Прямая дифференциальная линия шины RS-485 |
| `XP1:4` | `B` (RS-485-B) | `TP49` | Инверсная дифференциальная линия шины RS-485 |
| `XP1:5` | `+Line` | `TP8` | Плюс разговорной линии домофона |
| `XP1:6` | `LU2` | `TP6`, `TP46`, `TP51` | Линия детекции трубки 2 (вход МК `GPIO37` через триггер Шмитта `DD1`) |
| `XP1:7` | `LU1` | `TP7`, `TP45`, `TP50` | Линия детекции трубки 1 (вход МК `GPIO36` через триггер Шмитта `DD1`) |
| `XP1:8` | `-Line` | `TP9` | Минус разговорной линии домофона |
| `XP1:9` | `Open/1W` | `TP17` | Линия отпирания электрозамка / 1-Wire протокол |

> **Аппаратная перемычка R1 (0 Ом, SW-OpenDoor)**:  
> Соединяет клемму `XP1:9 (Open/1W)` с выходом `SW-OUT2` (полумост `PO2` драйвера `D2 TLE94112EL`). Это позволяет формировать прямой сильноточный импульс отпирания электромагнитного/электромеханического замка по команде микроконтроллера.

---

### 2. Локальная индикация: адресный светодиод LED1 (WS2812C, GPIO23)
Светодиод `LED1` смонтирован непосредственно на плате для локальной визуализации режимов работы без подключения терминала.
- Сигнальный вывод: `GPIO23` (`LEVISW_PIN_LED_WS2812`, контрольная точка `TP20`).
- Выход `LEDOUT`: контрольная точка `TP19` (для возможного каскадирования индикации).
- Питание: шина `+5VL`, развязывающий конденсатор `C5` (100 нФ).

#### Цветовая схема индикации в примере:
- **Мягкое зелёное «дыхание» (плавное изменение яркости)**: дежурный режим (Standby), плата исправна, шины питания в норме (`Power Good = 1`), клеммы под контролем.
- **Оранжевый / янтарный**: зафиксировано изменение состояния на линиях трубок `LU1` или `LU2` (абонентская трубка поднята).
- **Яркая бирюзовая вспышка (400 мс)**: формирование импульса отпирания замка двери на клемме `XP1:9 (Open/1W)`.
- **Постоянный синий**: активирован сервисный режим тестирования выходных клемм.
- **Мигающий красный (авария)**: сработала защита по питанию (`Power Good = 0` от `D3 TPS65261`, `TP60`).

---

### 3. Кнопка сервисного режима SW1 (MODE, GPIO27)
Тактовая кнопка `SW1` подключена к узлу `BUTTON` (`TP21`, `TP58`, `TP70`).

> **КРИТИЧЕСКАЯ ОСОБЕННОСТЬ СХЕМЫ**:  
> Вывод микроконтроллера `GPIO27` является **аппаратно разделяемым** между тремя узлами:
> 1. `RS-ON` — управление питанием трансивера RS-485 `DD2 MAX13487` через `R11` (1 кОм, pull-up `RN5` 10 кОм);
> 2. `BUTTON` — тактовая кнопка `SW1` через `R10` (4.7 кОм, pull-up `R9` 4.7 кОм к `+3.3V`);
> 3. На осмотренном экземпляре `CORN13/RN13` не установлена; GPIO27 не подключён к MC33879 IN5. Пользователь подтвердил LOW на IN5/IN6.
>
> В данном примере `GPIO27` сконфигурирован как вход с внутренней подтяжкой `GPIO_PULLUP_ENABLE`. Нажатие `SW1` замыкает узел через `R10` на `GND`. Встроенная программная фильтрация подавляет контактный дребезг.

#### Реакция на нажатие кнопки в примере:
- **Короткое нажатие (< 1 сек)**: инициирует проверочный импульс открытия замка двери на клемме `XP1:9` (`trigger_door_open_pulse()`).
- **Длинное нажатие (> 1 сек)**: включает/выключает сервисный режим перебора аналоговых маршрутов AMP1…AMP8 и отображения таблицы координат E.

---

### 4. Координатные выходы и отдельный AMP-селектор

- **Координата D — `XP2:1..8` (`D0..D7`, `TP27..TP34`)**: выходы `MC33879.S1..S8`. Это силовые каналы, управляемые по SPI; данный пример их не включает и не проверяет.
- **Координата E — `XP3:1..10` (`E0..E9`, `TP35..TP44`)**:  
  Подключён к выходам полумостов `PO1..PO12` драйвера `D2 TLE94112EL`. В примере отображается таблица нелинейного соответствия BSP:
  - `E0` (`XP3:1`, `TP35`) → полумост `PO1`;
  - `E1` (`XP3:2`, `TP36`) → полумост `PO5`;
  - `E2` (`XP3:3`, `TP37`) → полумост `PO7`;
  - `E3` (`XP3:4`, `TP38`) → полумост `PO9`;
  - `E4` (`XP3:5`, `TP39`) → полумост `PO6`;
  - `E5` (`XP3:6`, `TP40`) → полумост `PO4`;
  - `E6` (`XP3:7`, `TP41`) → полумост `PO3`;
  - `E7` (`XP3:8`, `TP42`) → полумост `PO10`;
  - `E8` (`XP3:9`, `TP43`) → полумост `PO11`;
  - `E9` (`XP3:10`, `TP44`) → полумост `PO8`.

**Отдельно об ADG1608:** по листу D8 он выбирает `+LINE → AMP1…AMP8 → XS3/LeviAMP`, а не D0…D7. В сервисном режиме этого примера переключается AMP-маршрут; D-координата через MC33879 не изменяется. При включённом SW-EN вход +LINE подключается к выбранному AMP-каналу, поэтому не использовать сервисный перебор на активной абонентской линии/трубке до проверки RN22…RN26 и внешней платы LeviAMP.

## Сборка и запуск примера

1. Откройте терминал с настроенным окружением ESP-IDF (>= 5.2):
```bash
cd examples/01_terminals_and_indication
idf.py set-target esp32
idf.py build
```

2. Подключите плату через программатор к разъёму `XP5` и выполните прошивку:
```bash
idf.py flash monitor
```
