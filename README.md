# LeviSW-MB v1.2 — прошивка, аппаратная поддержка и инженерный справочник

Репозиторий содержит программные компоненты для материнской платы домофонного коммутатора **LeviSW-MB v1.2** на базе **ESP32-PICO-V3**, демонстрационные проекты ESP-IDF, систему управления матрицей абонентов 8×10, программную FSM вызова и веб-справочник по схеме платы.

## Ветка проекта

Для текущей разработки используйте ветку `fix/safety-driver-audit`. Рабочая русифицированная версия документации и комментариев публикуется отдельно в ветке `i18n/russian-docs-comments`.

## Состав репозитория

- `bsp/levisw-mb-v1.2/` — пакет поддержки платы: карта GPIO, шины I2C/SPI, питание, телеметрия и аппаратные функции.
- `components/` — независимые программные компоненты:
  - `matrix_manager` — единственный владелец абонентской матрицы;
  - `call_controller` — конечный автомат обработки вызова;
  - `call_runtime` — интеграция декодера, детектора трубки и автомата;
  - `lu_decoder` — декодирование импульсного номера по линиям LU;
  - `handset_detector` — подтверждение снятия и укладки трубки;
  - `lu_event_dispatcher` — разветвление событий LU для декодера и мониторинга.
- `examples/` — отдельные проекты ESP-IDF для проверки узлов платы. Example 18 проверяет программный поток вызова без силовой коммутации; Example 19 объединяет BSP, декодер LU, FSM и Matrix Manager с закрытым по умолчанию физическим режимом.
- `examples/19_switchboard_controller/` — интегрированное приложение контроллера. По умолчанию работает с программной симуляцией матрицы; физический режим закрыт до проверки схемы и карты квартир.
- `docs/hardware/` — протокол проверки физической адресной карты квартир.
- `tools/matrix_address_map/` — проверка CSV-таблицы и генерация заголовка адресной карты.
- `src/`, `public/` — исходники и ресурсы веб-справочника по плате.

## Требования к среде разработки

### Прошивка ESP32

- Windows, Linux или macOS;
- ESP-IDF 6.0.x;
- целевая платформа ESP-IDF: `esp32`;
- Visual Studio Code с расширением Espressif IDF либо терминал с активированным окружением ESP-IDF.

### Веб-справочник

- Node.js 24 LTS (или версия, удовлетворяющая требованиям Vite 8);
- npm;
- Git.

## Получение исходников

```powershell
git clone --branch fix/safety-driver-audit https://github.com/megavatt05/LeviSW-MB-v1.2.git
cd LeviSW-MB-v1.2
```

Чтобы получить русифицированную ветку:

```powershell
git fetch origin
git checkout i18n/russian-docs-comments
```

## Запуск веб-интерфейса

Из корневого каталога репозитория:

```powershell
npm install
npm run dev
```

Откройте адрес, который выведет Vite; по умолчанию это `http://localhost:3000`.

Для production-сборки:

```powershell
npm run build
npm run preview
```

Файлы production-сборки создаются в каталоге `dist/`.

Встроенный AI-помощник использует переменную окружения `VITE_GEMINI_API_KEY`. Без неё справочник запускается в автономном режиме. Не помещайте реальный ключ в общедоступный репозиторий: переменные с префиксом `VITE_` попадают в клиентскую сборку.

## Сборка безопасного примера ESP-IDF

Начните с Example 18 — Call Runtime Monitor. Это наиболее безопасный проект для первого знакомства с FSM: его адаптер матрицы программный и не переключает физические выходы D/E.

Откройте ESP-IDF Terminal и выполните:

```powershell
cd examples/18_call_runtime_monitor
idf.py set-target esp32
idf.py build
```

Для прошивки после подключения платы:

```powershell
idf.py -p COMx flash monitor
```

Замените `COMx` фактическим номером COM-порта. Перед прошивкой проверьте интерфейс программирования и уровни сигналов по документации платы.

## Автономные тесты на ПК

Для тестирования чистых программных компонентов без платы нужны CMake и компилятор C. Пример:

```powershell
cmake -S components/call_runtime/tests -B build/call_runtime_tests
cmake --build build/call_runtime_tests
ctest --test-dir build/call_runtime_tests --output-on-failure
```

Тесты других компонентов запускаются аналогичным образом; точные команды приведены в README соответствующего компонента.

Проверка входной таблицы квартир:

```powershell
python3 -m unittest discover -s tools/matrix_address_map/tests -v
```

## Важные ограничения по безопасности

1. Example 18 имитирует матрицу программно. Он не проверяет силовую коммутацию на реальной плате.
2. Физическая карта соответствия квартир 1..80 выходам D/E не считается подтверждённой, пока не заполнен и независимо не проверен протокол непрерывности цепей.
3. Не подключайте абонентский жгут и не разрешайте силовую коммутацию, пока не проверены полярность, временные интервалы, безопасные состояния драйверов и адресная карта.
4. Не используйте демонстрационную последовательную карту в физическом профиле платы.
5. Аппаратные примеры, управляющие TLE94112EL, MC33879A, ADG1608 или силовыми шинами, запускайте только в соответствии с отдельными процедурами проверки и с ограничением тока источников питания.

Основной документ: [протокол проверки аппаратной матрицы](docs/hardware/LeviSW-MB-v1.2-matrix-commissioning.md).

## Порядок знакомства с проектом

1. Изучите этот файл и README в `bsp/levisw-mb-v1.2/`.
2. Просмотрите аппаратную карту GPIO и распределение устройств на I2C/SPI.
3. Соберите Example 18 для проверки Runtime и Example 19 для интеграции приложения.
4. Запустите автономные тесты компонентов.
5. Физические выходы разрешайте только после завершения аппаратной проверки, генерации карты 80 квартир и явного подтверждения профиля.
