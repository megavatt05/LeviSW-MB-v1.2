# Пример 19 — интегрированный контроллер коммутатора LeviSW-MB v1.2

Этот пример объединяет BSP платы, диспетчер событий LU, декодер импульсного номера, детектор снятия трубки, FSM вызова и Matrix Manager в одном приложении ESP-IDF.

## Что включено

- Инициализация BSP LeviSW-MB v1.2.
- Единственный потребитель очереди событий LU на уровне диспетчера.
- Отдельные очереди для декодера и диагностического монитора.
- Декодирование входного номера по LU1/LU2.
- FSM `STANDBY → CAPTURE_NUMBER → VALIDATE_TARGET → ROUTE_PREPARE → RINGING → ANSWER_VERIFY → TALKING → HANGUP`.
- Подтверждение снятия и укладки трубки.
- Матрица 8×10 через Matrix Manager с последовательностью Break-Before-Make.
- Контроль потери событий LU и фиксация состояния FAULT.
- Периодический контроль PGOOD, шин +V1/+V2 и диагностического регистра TLE94112 в физическом режиме.

## Режим по умолчанию — безопасная программная симуляция

По умолчанию `CONFIG_SWITCHBOARD_ENABLE_PHYSICAL_MATRIX=n`. В этом режиме приложение использует программный адаптер матрицы и последовательную карту, помеченную как утверждённую **только для симулятора**. Аппаратные выходы D/E не переключаются, EN-DE не поднимается, шины +V1/+V2 не включаются.

BSP и входы LU при этом инициализируются на реальной плате. Режим предназначен для проверки сборки, декодера, очередей, FSM и временной логики. Он не подтверждает электрическую работу матрицы.

## Сборка ESP-IDF 6.0

Из ESP-IDF Terminal:

```powershell
cd examples/19_switchboard_controller
idf.py set-target esp32
idf.py build
```

Прошивка и монитор:

```powershell
idf.py -p COMx flash monitor
```

Замените `COMx` номером COM-порта платы.

## Разрешение физического управления

Физический режим намеренно закрыт несколькими независимыми проверками. Для его включения требуется:

1. Заполнить все 80 строк `docs/hardware/LeviSW-MB-v1.2-apartment-map-template.csv` по фактическому жгуту, выполнить измерения непрерывности цепей и независимую проверку.
2. Сгенерировать `bsp/levisw-mb-v1.2/include/levisw_mb_v1_2_apartment_map_generated.h` штатным скриптом `tools/matrix_address_map/generate_matrix_address_map.py`.
3. Проверить напряжения +V1/+V2, уставки DA2/DA3, полярность E, токи, поведение EN-DE, выходов MC33879A/TLE94112EL и интервалы коммутации на макетной нагрузке.
4. В `idf.py menuconfig` включить `LeviSW-MB v1.2 — контроллер коммутатора → Разрешить физическое управление матрицей D/E`.
5. Явно подтвердить аппаратный профиль, разрешить включение +V1/+V2 при запуске, задать проверенные уставки DA2/DA3 и выбрать полярность LOW_SIDE или HIGH_SIDE.

При физической сборке без сгенерированной карты, без подтверждённого профиля или без явного выбора полярности компиляция завершается ошибкой. При запуске дополнительно проверяются чтение PGOOD и диапазон измеренных напряжений по INA226. Непроверенная или неполная карта не может быть подключена через Matrix Manager.

## Что пока не реализовано в электрическом тракте вызова

Существующая FSM управляет коммутацией абонентской пары и распознаванием снятия/укладки трубки. Она **не генерирует аналоговое напряжение звонка**, не формирует аудиосигнал и не управляет внешним аудиомодулем как законченным трактом. Для этого нужны проверенные электрическая схема и интерфейс дочерней платы усилителя/генератора вызова, а также подтверждённые временные параметры панели.

Значения декодера LU (120 мкс / 80 мс / два перехода на номер) и фильтры снятия/укладки трубки (60 мс) пока предварительные. Перед подключением абонентской панели их необходимо измерить на реальных сигналах.
