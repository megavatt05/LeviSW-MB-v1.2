# Пример 17: Тестирование «Бегущий огонь» для микросхемы D2 TLE94112EL (LeviSW-MB v1.2)

Проект предназначен для функционального тестирования и валидации драйвера единиц `D2 TLE94112EL` на плате коммутатора **LeviSW-MB v1.2** (схема `U210001-A E3`, Узел 11 `E10-OUT.SchDoc`).

---

## 🎯 Назначение и функционал

1. **Режим «Бегущий огонь» (Chaser)**:
   - **Фаза 1 (Прямой ход)**: последовательное включение High-Side ключей линий единиц `E0` $\to$ `E9` с переходом в Floating (Hi-Z).
   - **Фаза 2 (Обратный ход)**: бегущий огонь в обратном порядке `E9` $\to$ `E0`.
   - **Фаза 3 (Вспомогательные каналы)**: тестирование служебных выходов `PO2` (`SW-OUT2` / цепь замка двери `OpenD`) в импульсном режиме Low-Side и `PO12` (`SW-OUT12` / `TP152`) в режиме High-Side.
   - **Фаза 4 (Диагностика и защита)**: опрос системных регистров ошибок `SYS_DIAG_1` и чтение телеметрии шины питания `+V2` через монитор `INA226`.

2. **Аппаратная таблица соответствия матрицы единиц к клеммнику XP3**:
   | Линия матрицы | Контакт клеммника XP3 | Контрольная точка (TP) | Полумост TLE94112 | Индекс драйвера |
   |:-------------:|:---------------------:|:----------------------:|:-----------------:|:---------------:|
   | **E0**        | `XP3:1`               | `TP35`                 | **PO1**           | `TLE_HB1` (0)   |
   | **E1**        | `XP3:2`               | `TP36`                 | **PO5**           | `TLE_HB5` (4)   |
   | **E2**        | `XP3:3`               | `TP37`                 | **PO7**           | `TLE_HB7` (6)   |
   | **E3**        | `XP3:4`               | `TP38`                 | **PO9**           | `TLE_HB9` (8)   |
   | **E4**        | `XP3:5`               | `TP39`                 | **PO6**           | `TLE_HB6` (5)   |
   | **E5**        | `XP3:6`               | `TP40`                 | **PO4**           | `TLE_HB4` (3)   |
   | **E6**        | `XP3:7`               | `TP41`                 | **PO3**           | `TLE_HB3` (2)   |
   | **E7**        | `XP3:8`               | `TP42`                 | **PO10**          | `TLE_HB10` (9)  |
   | **E8**        | `XP3:9`               | `TP43`                 | **PO11**          | `TLE_HB11` (10) |
   | **E9**        | `XP3:10`              | `TP44`                 | **PO8**           | `TLE_HB8` (7)   |
   | **OpenD**     | Внутренняя цепь       | —                      | **PO2**           | `TLE_HB2` (1)   |
   | **SW-OUT12**  | `TP152`               | `TP152`                | **PO12**          | `TLE_HB12` (11) |

3. **Синхронная индикация**:
   - Адресный светодиод `LED1` (`WS2812C`, `GPIO23`, `TP20`) отображает цветовую фазу бегущего огня и статус завершения цикла без аварий.

## LU1/LU2: диспетчер событий и декодер номера

В примере используется единый поток raw-событий:

`BSP ISR → BSP queue → LU Event Dispatcher → decoder queue / monitor queue`

- Только задача `lu_dispatcher` читает BSP-очередь. Она копирует неизменённые события в две независимые очереди.
- `lu_decoder` — чистый C-модуль без GPIO и FreeRTOS. Он фильтрует короткие переходы, собирает пакет и выдаёт **кандидат** номера квартиры.
- `lu_monitor` сохраняет отдельную диагностику стабильных уровней с фильтром 5 мс. Этот фильтр не применяется к номерному декодеру.
- При переполнении очереди декодера текущий пакет сбрасывается, а уровни LU повторно синхронизируются по GPIO. Потерянный фронт не должен приводить к коммутации по сомнительному номеру.
- Выдача номера не включает драйверы, реле или матрицу. Маршрутизация в этом примере не реализована.

Начальные значения профиля декодера (120 мкс, 80 мс и 2 перехода на номер) взяты из исторических стендовых заметок и являются **предварительными**. До подключения линий домофона их нужно измерить на реальной панели. Декодер не способен обнаружить пропуск целого импульса из двух переходов без дополнительного правила кадрирования/контроля целостности.

### Автономные тесты декодера на ПК

Из корня репозитория:

```sh
cmake -S components/lu_decoder/tests -B build/lu_decoder_tests
cmake --build build/lu_decoder_tests
ctest --test-dir build/lu_decoder_tests --output-on-failure
```

Покрыты адреса 1–80, короткий ложный импульс, потеря одного перехода и выход номера за диапазон.

## Архитектура боевого контроллера (новые компоненты)

Добавлены независимые компоненты:

- `components/matrix_manager` — единственный владелец матрицы D/E, реализует
  break-before-make, одно активное пересечение, fail-safe отключение и блокировку
  повторного подключения после аппаратной ошибки.
- `components/call_controller` — FSM
  `STANDBY → CAPTURE_NUMBER → VALIDATE_TARGET → ROUTE_PREPARE → RINGING →
  ANSWER_VERIFY → TALKING → HANGUP`, с отдельным FAULT и ручным восстановлением.
- `components/matrix_manager_espidf` — адаптер абстрактных операций к BSP,
  MC33879A и TLE94112EL. Он использует BSP-таблицу нелинейного E→HB маппинга
  и дополнительный SPI-кадр чтения диагностики MC33879A.

**Важно:** пример 17 остаётся аппаратным тестом драйверов и пока продолжает
содержать прямое управление TLE/MC в тестовой задаче. Новые компоненты добавлены
в сборочную конфигурацию, но FSM ещё не запускается в этом примере. Не запускайте
два владельца матрицы одновременно. Следующим интеграционным изменением будет
отдельное приложение контроллера, где все прямые обращения к ADG/MC/TLE будут
заменены вызовами Call Controller → Matrix Manager.

Для принятия вызова FSM принимает семантические события от декодера и будущего
датчика трубки. Порог определения снятия трубки не задан: DD6 измеряет шину +V2,
а не абонентскую линию. Тайм-ауты в FSM по умолчанию отключены до измерения реальных
временных диаграмм домофонной панели.

Нативные тесты:
```sh
cmake -S components/matrix_manager/tests -B build/matrix_manager_tests
cmake --build build/matrix_manager_tests
ctest --test-dir build/matrix_manager_tests --output-on-failure

cmake -S components/call_controller/tests -B build/call_controller_tests
cmake --build build/call_controller_tests
ctest --test-dir build/call_controller_tests --output-on-failure
```


Тайм-аут разговора `ring_timeout_ms` отсчитывается от первого входа в RINGING
и не продлевается повторными неуспешными попытками подтверждения снятия трубки.
