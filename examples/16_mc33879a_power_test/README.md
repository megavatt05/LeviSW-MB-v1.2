# Проект тестирования питания и драйвера NXP MC33879A (LeviSW-MB v1.2)

Готовый проект для **ESP-IDF (>= 5.2 / v6.1)**, объединяющий пакет поддержки платы **LeviSW-MB v1.2** (`levisw-mb-v1.2`) и выделенный компонент драйвера **`components/mc33879a/`** для включения силовых шин питания и проверки микросхемы **D1 (`MC33879APEKR2`)**.

---

## Что делает проект

1. **Инициализирует шины платы (`levisw_bsp_init`)**:
   - `I2C-L` (`IO32 = SCL0`, `IO33 = SDA0`) для работы с `DD3 TCA9535` (`0x20`), потенциометрами `MCP4532` и мониторами `INA226` (`DD5 0x40`, `DD6 0x41`);
   - `SPI2` (`MOSI = IO7`, `MISO = IO9`, `SCLK = IO5`, `Mode 1`: `CPOL=0, CPHA=1`), где `CS1 = IO10` (`D2 TLE94112EL`) остаётся неактивным (`HIGH`), а `CS2 = IO8` (`TP114`) выделен для `D1 MC33879APEKR2`.
2. **Включает силовое питание для `D1 MC33879A`**:
   - Включает каналы `+V1` (`V1EN = 1`) и `+V2` (`V2EN = 1`, питает `VPWR` микросхемы `D1`) через расширитель `DD3 TCA9535`;
   - Проверяет сигнал **`PG` (Power Good)** и выводит в консоль измеренные значения напряжения и тока шин `+V1` и `+V2` от `INA226`.
3. **Включает и тестирует микросхему `D1 MC33879A` (`components/mc33879a`)**:
   - Переводит параллельные входы `IN5` (`IO27`) и `IN6` (`IO21`) в `0`, чтобы они не перекрывали SPI-управление выходами `OUT5`/`OUT6`;
   - Активирует вывод **`EN-DE` (`IO20`, `TP115`) = 1**;
   - Выполняет циклические проверки:
     - одновременное включение `OUT1 | OUT3`, затем добавление `OUT8`;
     - поочерёдное переключение каждого выхода `OUT1..OUT8` («бегущий бит»);
     - отключение всех выходов (`0x00`) с повторным опросом статуса (`mc33879a_read_faults`) с учётом задержки ответа в 1 SPI-цикл.

## Подключение выводов `D1 MC33879APEKR2` на плате LeviSW-MB v1.2

| Сигнал MC33879A | GPIO (`ESP32-PICO-V3`) | КТ | Примечание |
|---|---|---|---|
| `DI` (`MOSI`) | `IO7` | `TP113` | Общая шина `SPI2` |
| `DO` (`MISO`) | `IO9` | `TP111` | Общая шина `SPI2` |
| `SCLK` | `IO5` | `TP118` | Тактирование `SPI Mode 1` (`CPOL=0, CPHA=1`) |
| `CS` (`CS2 / CS-D`) | `IO8` | `TP114` | Внешняя подтяжка `RN19` 10 кОм к `+3.3V` |
| `EN` (`EN-DE`) | `IO20` | `TP115` | Внешний `pull-down RN19` 10 кОм (нужна `1` для работы) |
| `IN5` | GPIO отсутствует | D1:19 | `CORN13/RN13` DNP; не связан с GPIO27; LOW подтверждён пользователем |
| `IN6` | GPIO отсутствует | D1:14 | `CORN13/RN13` DNP; не связан с GPIO21; LOW подтверждён пользователем |

## Сборка, прошивка и запуск монитора

```bash
cd examples/16_mc33879a_power_test
idf.py set-target esp32
idf.py build
idf.py -p COM10 flash monitor
```

*(Замените `COM10` на ваш актуальный COM/tty порт. Выход из монитора: `Ctrl + ]`)*.

## Диагностика по ответу `FAULT / RX`

У `MC33879A` диагностический байт `RX[7:0]` приходит со сдвигом на **один цикл SPI** и отражает состояние стоков `OUT8..OUT1`:
- При **выключенном** выходе (`0`) и отсутствии нагрузки (Open Load) внутренняя подтяжка удерживает высокий уровень на стоке $\rightarrow$ соответствующий бит `RX` равен **`1`**.
- При **включённом** выходе (`1`) без КЗ ключ замыкает выход на `GND` $\rightarrow$ соответствующий бит `RX` сбрасывается в **`0`**.
- Если при переключении выходов `RX` всегда `0x00` или `0xFF`, проверьте в логах `PG` и напряжение `+V2` (`VPWR`), а также уровни на `TP115` (`EN-DE`), `TP114` (`CS2`) и `VDD` микросхемы `D1`.
