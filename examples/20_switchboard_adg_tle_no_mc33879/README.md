# Example 20 — матрица квартир ADG1608 + TLE94112 без MC33879

**Плата:** LeviSW-MB v1.2 / ESP32-PICO-V3  
**Среда:** ESP-IDF 6.0.x, target `esp32`  
**Рабочая ветка:** `feature/switchboard-no-mc33879`

## 1. Принятая топология

В этом проекте используется указанная пользователем модель матрицы:

- **Десятки D0–D7 — DA1 ADG1608BR.** Адрес A0/A1/A2 и SW-EN задаются через TCA9535 DD3.
- **Единицы E0–E9 — D2 TLE94112EL.** Используются десять квартирных полумостов с нелинейным соответствием PO.
- **D1 MC33879APEKR2 не участвует в выборе квартиры.** В BSP регистрация этого SPI-устройства сделана опциональной и по умолчанию выключена через `CONFIG_LEVISW_ENABLE_MC33879=n`.

ADG1608 является 8:1 аналоговым мультиплексором. В этой модели координата D задаётся выбором одного канала ADG1608; отдельная команда в MC33879 для D не отправляется. В адаптере `set_d_mask()` — проверка согласованности маски с выбранным адресом ADG1608, а не управление силовым выходом.

### Важное расхождение с действующим аудитом схемы

В инженерных документах ветки `docs/hardware-reference` зафиксирована другая трассировка листа D8: ADG1608 S1..S8 идут в сети AMP1..AMP8 и на XS3/LeviAMP, тогда как MC33879 S1..S8 идут в D0..D7 и на XP2. Полный AMP→VOffset→D путь ещё не доказан по pin-to-pin, но по текущей КД нельзя считать ADG1608 прямым источником D0..D7.

Поэтому D=ADG1608 в Example 20 — **экспериментальная модель по уточнению пользователя**, а не подтверждённое электрическое заключение. Для физической сборки добавлена отдельная защёлка Kconfig: `SWITCHBOARD_ADG_IS_D_PATH_CONFIRMED`. Она по умолчанию выключена и должна оставаться выключенной, пока прозвонкой на конкретной плате и жгуте не доказано, что выбранный ADG-канал действительно приходит на соответствующую координату D квартиры без MC33879.

### Физическая таблица E

| Линия | TLE94112 | Полумост | Контрольная точка |
|---|---:|---:|---:|
| E0 | PO1 | HB1 | TP35 |
| E1 | PO5 | HB5 | TP36 |
| E2 | PO7 | HB7 | TP37 |
| E3 | PO9 | HB9 | TP38 |
| E4 | PO6 | HB6 | TP39 |
| E5 | PO4 | HB4 | TP40 |
| E6 | PO3 | HB3 | TP41 |
| E7 | PO10 | HB10 | TP42 |
| E8 | PO11 | HB11 | TP43 |
| E9 | PO8 | HB8 | TP44 |

PO2 / OpenD и PO12 / SW-OUT12 не входят в квартирные координаты E0–E9. Адаптер переводит в FLOATING и переключает только десять квартирных E-каналов; он не использует общий вызов `set_all_hb_state()` для управления квартирной матрицей.

### Порядок коммутации

1. Отключить SW-EN ADG1608 (Hi-Z).
2. Перевести E0–E9 в FLOATING.
3. Установить адрес D0–D7 на A0/A1/A2.
4. Установить ровно один выбранный E в заданное состояние LOW_SIDE или HIGH_SIDE.
5. Выдержать время стабилизации и включить SW-EN ADG1608.
6. При размыкании сначала отключить ADG1608, затем перевести выбранный E в FLOATING и отключить драйверы.

Времена Matrix Manager пока являются предварительными настройками ПО. Их нужно подтвердить осциллографом на реальной плате.

## 2. Что реализовано

- Matrix Manager — единственный владелец матрицы; адрес квартиры преобразуется через таблицу D/E, а не вычисляется из номера во время работы.
- Физический адаптер `matrix_manager_adg_tle` управляет ADG1608 через TCA9535 и E-каналами через специализированный LSB-first драйвер TLE94112.
- LU1 / LU2 — реальные входы GPIO36 / GPIO37 от входного буфера DD1. События с временными метками поступают в LU Decoder и Call Runtime.
- FSM вызова: STANDBY → CAPTURE_NUMBER → VALIDATE_TARGET → ROUTE_PREPARE → RINGING → ANSWER_VERIFY → TALKING → HANGUP / STANDBY.
- ALARM-IN — отдельный вход P1.5 TCA9535 от XS2:11 внешнего аудиомодуля. Это не вход номера квартиры и не вход LU.
- SOUND1 / SOUND2 — DAC GPIO25 / GPIO26 на XS2:4 / XS2:6. Добавлен опциональный тестовый аудиотон и периодический цикл вызова.

## 3. Что означает «звонок» в этом примере

Опциональный DAC-режим создаёт **низкоуровневый аналоговый тестовый тон** на SOUND1/SOUND2 и может включать выбранные ENAMP1..3. Это проверка аудиовхода внешнего модуля LeviAMP.

Это **не генератор высоковольтного переменного напряжения звонка** для аналоговой трубки. Внутренняя схема LeviAMP и реальный ring-feed генератор здесь не реализованы и не считаются подтверждёнными.

По умолчанию `CONFIG_SWITCHBOARD_ENABLE_DAC_RING=n` и `CONFIG_SWITCHBOARD_RING_AMP_MASK=0`: FSM показывает RINGING в журнале, физический аудиотон и усилители не включаются. После проверки входного уровня LeviAMP можно отдельно включить DAC и указать проверенный ENAMP-канал.

## 4. Сборка — безопасная конфигурация по умолчанию

Из ESP-IDF Terminal:

```powershell
cd examples/20_switchboard_adg_tle_no_mc33879
idf.py set-target esp32
idf.py build
```

Прошивка и монитор:

```powershell
idf.py -p COMx flash monitor
```

По умолчанию физический режим матрицы и DAC-звонок отключены. EN-DE остаётся LOW, ADG1608 не включается, TLE не переключает квартирные выходы, а карта 1..80 используется только в RAM-симуляторе. MC33879 не регистрируется на SPI2.

## 5. Тестирование входов и FSM

После старта в журнале должны быть видны уровни LU1/LU2 и ALARM-IN. Runtime ждёт импульсный номер на одной из линий LU. После завершения корректного пакета он запрашивает маршрут квартиры в Matrix Manager. В симуляции физические D/E не переключаются.

При переходе в RINGING ring worker запускает каденцию тестового тона, только если DAC-режим явно включён. При подтверждении снятия трубки сигнал останавливается, маршрут остаётся подключённым для разговора. При устойчивом On-Hook маршрут размыкается.

Полярность LU и параметры импульсного номера из существующих модулей являются предварительными и требуют измерения на конкретной панели. ALARM-IN по умолчанию только логируется; аварийная интерпретация выключена, пока не подтверждена его активная полярность.

## 6. Разрешение физической матрицы

Физический режим по умолчанию запрещён. Перед его включением:

1. Заполнить все 80 записей физической адресной карты D/E в CSV-шаблоне.
2. Выполнить прозвонку каждой пары и независимую проверку по протоколу ввода матрицы в эксплуатацию.
3. Подтвердить по конкретной плате и жгуту соответствие каналов ADG1608 координатам D0–D7.
4. Подтвердить полярность E-выхода (LOW_SIDE / HIGH_SIDE) на эквиваленте нагрузки.
5. Проверить уровни питания, EN-DE, последовательность break-before-make и переходные процессы.

После этого в `idf.py menuconfig` включить физическую матрицу, подтверждение профиля, явное разрешение питания +V1/+V2 и выбранную полярность E. Без проверенного сгенерированного заголовка карты и полярности физическая конфигурация не собирается.

Протокол: `docs/hardware/LeviSW-MB-v1.2-matrix-commissioning.md`.

## 8. Файлы проекта

- `components/matrix_manager_adg_tle/` — адаптер D=ADG1608 и E=TLE94112 без MC33879.

- `Kconfig.projbuild` — разрешения физического режима, DAC-тона и мониторинга ALARM-IN.

## 9. Первые проверки на реальной плате

- D0..D7: A0/A1/A2 и SW-EN на TP64..TP67, затем выходы S1..S8 ADG1608 и их фактическое соответствие квартирным линиям.
- E0..E9: соответствующие POx на TP35..TP44, активная полярность и состояние FLOATING.
- LU1/LU2: уровни в покое, при импульсах номера, во время звонка, при снятии и укладке трубки.
- ALARM-IN: фактический активный уровень на XS2:11.
- SOUND1/SOUND2: амплитуда и смещение DAC на XS2:4/6 и допустимый уровень входа внешнего LeviAMP.

Этот проект задаёт программную модель для проверки кода. Он не доказывает, что внешний тракт VOffset/LeviAMP не нужен для формирования полного двухпроводного сигнала трубки.
